Variablen

Drei Schlüsselwörter, von denen du zwei brauchst. const ist der Normalfall, let die Ausnahme, var die Vergangenheit.

?

Fragen zum Erklären

  1. Was ist ECMAScript, und was bedeutet ES6?
  2. Wann nimmst du const, wann let, wann var?
  3. Was ist Block Scope, was Global Scope?
  4. Was ist der Unterschied zwischen JavaScript im Browser und auf dem Server?
Wo du nachschauen kannst

Stichwörter zum Suchen: ECMAScript, ES6, „var let const difference“, „block scope“, „client-side vs server-side JavaScript“. Formulier die Antworten in eigenen Worten — abgeschrieben nützen sie dir nichts.

●○○ leicht

Vier Zeilen, drei Fehler

Dieser Code läuft nicht durch. Finde jeden Fehler, korrigiere ihn und sag in einem Satz, warum die Zeile so nicht geht.

const mwst = 0.19;
mwst = 0.07;

let hersteller;
const gruendung;

var zaehler = 0;
zaehler = zaehler + 1;
Tipp, wenn du nicht weiterkommst

Drei der vier Blöcke brechen eine Regel. Führ den Code aus — die Konsole nennt dir zwei der drei Fehler mit Namen und Zeile. Der dritte ist kein Fehler des Browsers, sondern eine Regel aus dem Fragenblock oben. Und einer der vier Blöcke ist völlig in Ordnung.

●●○ mittel

Block Scope sichtbar machen

Sag für beide Blöcke voraus, was in der Konsole landet. Dann ausführen und den Unterschied erklären.

// Block A
if (true) {
  var a = "mit var";
}
console.log(a);

// Block B
if (true) {
  let b = "mit let";
}
console.log(b);
Tipp, wenn du nicht weiterkommst

Die Blöcke sind identisch bis auf ein Wort. Führ sie einzeln aus, nicht zusammen — sonst bricht der erste Fehler das Skript ab und du siehst den zweiten Fall nie.

●●○ mittel

Zu früh zugegriffen

Zwei fast gleiche Blöcke, zwei verschiedene Ergebnisse. Welche Ausgabe kommt jeweils, und warum?

console.log(preisA);
var preisA = 129;

console.log(preisB);
let preisB = 129;
Tipp, wenn du nicht weiterkommst

Ein Block gibt einen Wert aus, der andere bricht ab. Nachlesen unter dem Stichwort Hoisting. Überleg beim Vergleich: Welche der beiden Meldungen hätte dir bei einem echten Fehler mehr geholfen?

Datentypen und Operatoren

Was für Werte es gibt, und was die Zeichen zwischen ihnen bedeuten. Der Abschnitt, der später die meisten Bugs verhindert.

?

Fragen zum Erklären

  1. Welche Datentypen gibt es in JavaScript?
  2. Was macht der typeof-Operator?
  3. Was ist der Unterschied zwischen alert, prompt und confirm?
  4. Welche Zuweisungsoperatoren gibt es, welche logischen?
Wo du nachschauen kannst

Stichwörter: „JavaScript data types“, typeof, „alert prompt confirm“, „assignment operators“, „logical operators“.

●○○ leicht

Zu jedem Datentyp ein Wert

Leg für jeden Datentyp eine Variable mit einem sinnvollen Wert aus dem Padel-Shop an. Gib danach von jeder typeof aus. Sag die acht Ausgaben vorher.

Tipp, wenn du nicht weiterkommst

Es sind sieben primitive Typen plus object. Zwei Ergebnisse werden dich überraschen — bei null und beim Array. Beide haben denselben Grund, such nach „typeof null bug“.

●○○ leicht

Nach dem Namen fragen

Bau eine kleine Begrüßung mit allen drei Browser-Fenstern: frag mit prompt nach dem Namen, lass mit confirm bestätigen, ob der Newsletter gewünscht ist, und zeig das Ergebnis mit alert. Fängt der Nutzer den Abbruch ab? Prüf, was bei „Abbrechen" passiert.

Tipp, wenn du nicht weiterkommst

Bau es in Schritten: prompt aufrufen, Ergebnis in eine Variable, dann prüfen, dann weiter. Klick bei einem Versuch bewusst auf „Abbrechen“ und log, was zurückkommt — das musst du abfangen, bevor du eine String-Methode auf den Wert anwendest. Prüf mit typeof, was du bekommst, wenn du eine Zahl eintippst.

●○○ leicht

Zuweisungsoperatoren am Warenkorb

Start ist let summe = 100;. Schreib für jeden Schritt eine Zeile mit dem passenden Kurz-Operator und sag die Zwischenergebnisse vorher.

  1. 29,90 dazu
  2. 10 Rabatt abziehen
  3. verdoppeln (zwei Sätze)
  4. durch 4 teilen (vier Ratenzahlungen)
  5. Rest bei Division durch 10 (für die Rundungsprüfung)
  6. Positionszähler anzahl um 1 erhöhen
Tipp, wenn du nicht weiterkommst

Jeder Schritt ist eine Kurzform aus zwei Zeichen. Für den Rest einer Division gibt es ein eigenes Zeichen. Und der Zähler braucht dasselbe Zeichen zweimal. Log nach jedem Schritt, sonst siehst du den Fehler nicht.

●●○ mittel

Darf bestellt werden?

Schreib die Bedingung mit &&, || und !. Bestellen darf, wer angemeldet ist und (genug Guthaben hat oder auf Rechnung kaufen darf) — solange das Konto nicht gesperrt ist.

const angemeldet = true;
const guthaben = 0;
const rechnungskauf = true;
const gesperrt = false;
Tipp, wenn du nicht weiterkommst

Übersetz den Satz Wort für Wort: „und“, „oder“, „nicht“. Ein Klammerpaar brauchst du — überleg, welche zwei Bedingungen zusammengehören. Prüf danach den Fall „0 Guthaben, aber Rechnungskauf erlaubt“: kommt der durch?

●●○ mittel

Doppelt oder dreifach

true oder false? Alle acht Zeilen vorhersagen, dann prüfen.

1 == "1"
1 === "1"
null == undefined
null === undefined
NaN == NaN
[] == false
"0" == false
"" == 0
Tipp, wenn du nicht weiterkommst

Sechs der acht Zeilen sind true. Die Regel steht im Fragenblock. Für zwei Zeilen musst du wissen, wozu JavaScript [] und "" macht, wenn es sie in eine Zahl umwandelt — und eine Zeile ist mit sich selbst nicht gleich.

●●○ mittel

Die acht Falsy-Werte

Welche dieser Werte sind falsy, also in einem if so viel wert wie false? Streich sie an und zähl, wie viele es insgesamt gibt.

0    -0    ""    " "    "0"    "false"    []    {}
null    undefined    NaN    0n    false
Tipp, wenn du nicht weiterkommst

Es ist eine feste Liste mit acht Einträgen, such nach „falsy values“. Rate nicht bei [], {} und "0" — schreib ein if drum und probier es aus.

Verzweigungen

Drei Werkzeuge für eine Entscheidung. Welches passt, entscheidet die Form der Frage — nicht der Geschmack.

?

Fragen zum Erklären

  1. Wie sind if, else if und else aufgebaut?
  2. Wann nimmst du ein switch statt einer if-Kette?
  3. Was ist der Ternär-Operator, und wann lohnt er sich?
Wo du nachschauen kannst

Stichwörter: „if else“, „switch statement“, „ternary operator“ (auch: conditional operator).

●○○ leicht

Versandkosten staffeln

Schreib versand(warenwert) nach dieser Staffel: unter 25 € kostet der Versand 5,90 €, von 25 bis unter 100 € kostet er 2,90 €, ab 100 € ist er frei. Negative Werte ergeben null. Teste danach die Ränder: -1, 0, 24.99, 25, 99.99, 100.

Tipp, wenn du nicht weiterkommst

Drei if reichen, wenn du die Grenzen in der richtigen Reihenfolge abfragst — dann brauchst du kein &&. Kehr früh zurück statt zu verschachteln. Und teste am Ende wirklich alle sechs Werte aus der Aufgabe, besonders 25 und 100.

●○○ leicht

switch mit gemeinsamen Fällen

lieferzeit(status) bekommt "lager", "bestellt", "vorbestellung" oder "ausverkauft". Lager liefert "1–2 Tage", bestellt und Vorbestellung beide "5–7 Tage", ausverkauft "nicht lieferbar", alles Unbekannte "bitte anfragen". Nutz ein switch und fass die gleichen Fälle zusammen.

Tipp, wenn du nicht weiterkommst

Zwei der vier Fälle liefern dasselbe Ergebnis. Such nach „switch fallthrough“ — mehrere case dürfen sich einen Block teilen. Denk an den Fall für alles Unbekannte.

●●○ mittel

Vier Ebenen flach klopfen

Schreib die Funktion so um, dass sie höchstens eine Einrückungsebene tief ist. Das Verhalten bleibt gleich.

function darfBestellen(nutzer) {
  if (nutzer) {
    if (nutzer.aktiv) {
      if (nutzer.guthaben > 0) {
        return true;
      } else {
        return false;
      }
    } else {
      return false;
    }
  } else {
    return false;
  }
}
Tipp, wenn du nicht weiterkommst

Dreh jede Bedingung um und kehr sofort zurück, wenn sie zutrifft. Der letzte Schritt ist der interessante: Die innerste if/else-Konstruktion lässt sich auf eine Zeile ohne if eindampfen — überleg, was der Vergleich > 0 selbst schon für einen Wert ergibt.

Schleifen

Fünf Formen, ein Zweck: etwas mehrfach tun. Welche du nimmst, hängt davon ab, ob du zählst oder durch eine Liste gehst.

?

Fragen zum Erklären

  1. Welche Arten von Schleifen gibt es? Welche nimmst du am liebsten und warum?
  2. Was ist der Unterschied zwischen for und forEach?
  3. Was machen break und continue?
  4. Wann läuft eine do...while-Schleife anders als eine while-Schleife?
Wo du nachschauen kannst

Stichwörter: „for while do-while“, „for...of vs for...in“, forEach, „break continue“.

●○○ leicht

FizzBuzz

Zähl mit einer for-Schleife von 1 bis 30. Gib bei Vielfachen von 3 "Fizz" aus, bei Vielfachen von 5 "Buzz", bei Vielfachen von beiden "FizzBuzz", sonst die Zahl.

Tipp, wenn du nicht weiterkommst

Die Reihenfolge der Bedingungen entscheidet alles. Welche Zahl passt in zwei Bedingungen gleichzeitig, und welche davon muss zuerst geprüft werden? Für „ist teilbar durch“ brauchst du den Rest-Operator.

●●○ mittel

while und do...while

Ein Warenkorb hat 1.000 € Budget. Schläger kosten 249 € pro Stück. Zähl mit while, wie viele hineinpassen. Dann bau dieselbe Rechnung als do...while und finde den Fall, in dem beide unterschiedliche Ergebnisse liefern.

Tipp, wenn du nicht weiterkommst

Solange noch Budget für einen weiteren Schläger da ist: abziehen und hochzählen. Für den Unterschied der beiden Varianten setz das Budget auf 0 und lass beide laufen — dann siehst du es sofort.

●●○ mittel

for...of, for...in und break

Geh mit for...of durch die Preise und addiere sie — überspring dabei mit continue alle Nullwerte und brich mit break ab, sobald die Summe 500 übersteigt. Danach: geh mit for...in durch das Objekt und gib jedes Schlüssel-Wert-Paar aus.

const preise = [249, 0, 89, 199, 0, 129, 349];
const schlaeger = { name: "Vertex 04", preis: 249, form: "diamant" };
Tipp, wenn du nicht weiterkommst

continue und break stehen je in einem if. Achte darauf, an welcher Stelle im Schleifenkörper sie stehen müssen — vor oder nach dem Addieren macht einen Unterschied. Beim Objekt: Probier den Zugriff einmal mit Punkt und einmal mit eckigen Klammern.

●●○ mittel

forEach über querySelectorAll

Leg im HTML fünf <div class="item"> an. Hol sie alle mit querySelectorAll und gib jedem per forEach die Klasse -sichtbar. Jedes dritte bekommt zusätzlich -hervorgehoben — dafür brauchst du den zweiten Parameter von forEach.

Tipp, wenn du nicht weiterkommst

forEach übergibt dir mehr als nur das Element — schau in der Doku nach dem zweiten Parameter. Für „jedes dritte“ brauchst du wieder den Rest-Operator, aber denk daran, ab welcher Zahl gezählt wird.

Funktionen

Eine Funktion nimmt Werte an und gibt einen zurück. Alles, was sie darüber hinaus tut, ist eine Nebenwirkung — und die willst du sehen können.

?

Fragen zum Erklären

  1. Was ist eine Funktion, und wofür brauchst du sie?
  2. Was ist ein Parameter, was ein Argument?
  3. Was macht return — und was passiert ohne?
  4. Was ist der Unterschied zu einer Arrow-Funktion?
Wo du nachschauen kannst

Stichwörter: „function declaration“, „parameter vs argument“, return, „arrow function“, „this in arrow function“.

●○○ leicht

Bruttopreis rechnen

Schreib brutto(netto, satz), das den Bruttopreis auf zwei Stellen gerundet zurückgibt. Fehlt der Steuersatz, gilt 19 %. Danach: gib das Ergebnis nicht in der Funktion aus, sondern verwende den Rückgabewert für eine Summe aus drei Artikeln.

Tipp, wenn du nicht weiterkommst

Für den Standardwert gibt es eine Schreibweise direkt im Funktionskopf. Zum Runden auf zwei Stellen: mal 100, runden, geteilt durch 100. Und der wichtigste Punkt: Die Funktion muss den Wert zurückgeben, nicht ausgeben — sonst kannst du die Summe am Ende nicht bilden.

●●○ mittel

Globale Variable gegen Rückgabewert

Beide Funktionen zählen den Warenkorb hoch. Führ beide aus und erklär, warum die zweite die bessere ist.

let anzahl = 0;

// Variante A: aendert die globale Variable
function hinzufuegenA() {
  anzahl++;
}

// Variante B: rechnet und gibt zurueck
function hinzufuegenB(aktuell) {
  return aktuell + 1;
}
Tipp, wenn du nicht weiterkommst

Führ beide aus und schau nicht auf das Ergebnis, sondern auf die Aufrufstelle: Bei welcher der beiden erkennst du am Aufruf, was sie verändert? Stell dir vor, drei weitere Funktionen fassen dieselbe Variable an.

●○○ leicht

Funktion mit eingebauter Prüfung

Schreib rabattStufe(summe): ab 500 € gibt es 15 %, ab 200 € 10 %, ab 100 € 5 %, darunter nichts. Bei fehlender oder unbrauchbarer Eingabe (kein Zahlenwert, negativ) gib 0 zurück statt zu rechnen.

Tipp, wenn du nicht weiterkommst

Die Prüfung der Eingabe kommt zuerst und kehrt früh zurück, wie in Aufgabe 12. Für „ist das überhaupt eine Zahl“ brauchst du typeof — und einen Zusatz, weil ein bestimmter Wert sich als Zahl ausgibt, ohne mit einem zu rechnen zu sein. Stichwort: Number.isNaN.

●○○ leicht

Drei Schreibweisen, eine Funktion

Schreib diese Funktion einmal als Arrow-Funktion mit Rumpf und einmal mit implizitem return. Dann probier aus: Was passiert, wenn du eine Arrow-Funktion vor ihrer Zeile aufrufst?

function flaeche(breite, hoehe) {
  return breite * hoehe;
}
Tipp, wenn du nicht weiterkommst

Die zweite Variante kommt ohne geschweifte Klammern und ohne return aus. Probier zusätzlich, ein Objekt zurückzugeben — das geht schief, und die Lösung ist ein einzelnes Klammerpaar. Für die letzte Frage: Ruf die Arrow-Funktion eine Zeile über ihrer Definition auf.

Arrays

Die Liste ist die wichtigste Datenstruktur im Frontend. Die Frage bei jeder Methode: verändert sie das Original oder gibt sie ein neues Array zurück?

?

Fragen zum Erklären

  1. Was ist ein Array, und wie legst du eines an (zwei Wege)?
  2. Wie kommst du an das erste und das letzte Element?
  3. Was machen push, pop, shift und unshift?
  4. Was ist der Unterschied zwischen splice, slice und concat?
Wo du nachschauen kannst

Stichwörter: „array literal“, length, „push pop shift unshift“, „splice vs slice“, concat, „mutating array methods“.

●○○ leicht

Index, Länge, Austausch

Arbeite die Liste der Reihe nach ab und gib nach jedem Schritt das Array in der Konsole aus.

const formen = ["rund", "tropfen", "diamant", "hybrid"];
  1. Gib das erste Element aus.
  2. Gib das letzte Element aus — ohne die 3 hinzuschreiben.
  3. Gib die Länge aus.
  4. Ersetz das erste Element durch "oval".
  5. Gib das Element an Position 10 aus. Was passiert?
Tipp, wenn du nicht weiterkommst

Für das letzte Element ohne die 3: length minus eins. Es gibt auch eine neuere Methode, die negative Indizes annimmt. Bei Position 10 kommt kein Fehler — schau genau hin, was stattdessen kommt, und überleg, wo der Fehler dann auftauchen würde.

●○○ leicht

Der Warenkorb wächst und schrumpft

Start ist ein leerer Warenkorb. Führ die Schritte aus und sag jeweils vorher, was das Array danach enthält und was die Methode zurückgibt.

Tipp, wenn du nicht weiterkommst

Achte nicht nur auf das Array, sondern auf den Rückgabewert jeder Methode: Speicher ihn in einer Variablen und log ihn. Zwei der vier geben etwas anderes zurück als die anderen zwei.

●●○ mittel

splice, slice, concat

Diese drei sehen ähnlich aus und verhalten sich verschieden. Führ jede Zeile aus und prüf danach mit console.log(schlaeger), ob das Original noch heil ist.

const schlaeger = ["Vertex 04", "Viper", "Nerox", "Bela", "Metalbone"];
const zubehoer = ["Griffband", "Schutzband"];
  1. Kopier die ersten zwei Schläger in ein neues Array.
  2. Entfern "Nerox" aus dem Original.
  3. Setz an Position 1 "Alpha" ein, ohne etwas zu löschen.
  4. Häng das Zubehör an — als neues Array, ohne das Original anzufassen.
Tipp, wenn du nicht weiterkommst

Log nach jedem Schritt das Original. Zwei der drei Methoden lassen es unangetastet, eine nicht. Und pass auf: Die zweite Zahl bedeutet bei den beiden ähnlich klingenden Methoden etwas Verschiedenes — einmal eine Position, einmal eine Anzahl. Schau in der Doku nach, welche was ist.

●●○ mittel

Eine Liste von Objekten durchsuchen

So kommen Daten aus einer API — ein Array voller Objekte. Beantworte jede Frage mit einer Zeile.

const sortiment = [
  { id: 1, name: "Vertex 04", preis: 249, lager: 4 },
  { id: 2, name: "Viper", preis: 219, lager: 0 },
  { id: 3, name: "Nerox", preis: 199, lager: 12 },
  { id: 4, name: "Bela", preis: 229, lager: 2 },
];
  1. Alle Namen als einfaches Array.
  2. Nur die lieferbaren Schläger.
  3. Der Schläger mit id: 3.
  4. Ist überhaupt etwas ausverkauft?
  5. Der Gesamtwert des Lagers (Preis × Bestand).
Tipp, wenn du nicht weiterkommst

Für jede der fünf Fragen gibt es eine passende Array-Methode: umformen, aussieben, einen einzelnen finden, prüfen ob mindestens einer zutrifft. Achte auf den Unterschied zwischen „gib mir das Element“ und „gib mir eine Liste“. Für die Summe reicht eine Schleife aus Thema 04.

●○○ leicht

Fünf Wege, ein Element

Bau dieses HTML und hol jedes Element mit einer anderen Methode. Gib alle fünf in der Konsole aus und schau dir genau an, was jeweils zurückkommt.

<h1 id="titel">Padel-Shop</h1>

●●○ mittel

innerHTML gegen textContent

const eingabe = '<strong>Angebot</strong> <img src=x onerror="alert(1)">';
Tipp, wenn du nicht weiterkommst

●●○ mittel

Aussehen aus JavaScript ändern

Färb die Überschrift rot, gib ihr 2rem Abstand nach unten und einen grauen Hintergrund — über element.style. Lies danach die Schriftgröße aus. Was liefert titel.style.fontSize, wenn die Größe aus dem CSS kommt?

Tipp, wenn du nicht weiterkommst

CSS-Eigenschaften mit Bindestrich heißen in JavaScript anders — probier marginBottom. Werte sind Strings mit Einheit. Beim Auslesen bekommst du einen leeren String; überleg, woher die Größe eigentlich kommt, und such dann nach getComputedStyle.

●●○ mittel

</a>
Tipp, wenn du nicht weiterkommst

Es gibt zwei Wege an ein data-Attribut. Der bequemere schreibt die Namen anders — Bindestriche verschwinden, so wie beim style in Aufgabe 27. Und log mit typeof, was du zurückbekommst, bevor du damit rechnest.

●●○ mittel

Eine Produktkarte selbst bauen

Erzeug per JavaScript eine Karte aus <div>, <h3> und <p>, häng sie in <div id="liste"></div> ein und gib ihr die Klasse karte. Hol dir danach über den Baum das Elternelement und das nächste Geschwisterelement.

Tipp, wenn du nicht weiterkommst

Bau die Karte im Speicher fertig zusammen und häng sie erst am Ende ein — eine Zeile statt drei verteilter. Bei den Geschwistern: Probier einmal nextSibling und einmal nextElementSibling und vergleich, was in der Konsole steht. Das Ergebnis erklärt, warum es zwei Varianten gibt.

// 09

Event Listener

Auf etwas reagieren, das der Nutzer tut. Der Moment, in dem die Seite anfängt, eine Anwendung zu sein.

?

Fragen zum Erklären

  1. Was ist ein Event Listener?
  2. Welche Event-Typen gibt es außer click?
  3. Gibt es einen anderen Weg, eine Funktion auf einen Klick zu binden — und warum nimmt man ihn nicht?
  4. Was macht removeEventListener, und was ist die Bedingung dafür?
  5. Was steckt im Parameter event?
Wo du nachschauen kannst

Stichwörter: addEventListener, „event types“, „inline onclick“, removeEventListener, „event object“, event.target.

●○○ leicht

Der erste Klick

Leg einen Button und ein <div class="box"> an. Such den Button per JavaScript, speicher ihn in einer Konstante und färb bei jedem Klick die Box in einer Farbe. Ruf dabei eine benannte Funktion auf, keine anonyme.

Tipp, wenn du nicht weiterkommst

Beim Registrieren übergibst du die Funktion ohne Klammern. Probier bewusst auch die Variante mit Klammern aus und erklär, was dann passiert und wann — das ist der häufigste Fehler in diesem Thema. Die Farbe selbst gehört ins CSS, du setzt nur eine Klasse.

●●○ mittel

Was im event steckt

Häng an eine Produktliste einen einzigen Listener und finde über event heraus, auf welche Karte geklickt wurde. Lies die Produkt-ID aus dem Data-Attribut und gib sie aus.

<div id="liste">
  <div class="karte" data-produkt-id="1"><h3>Vertex 04</h3></div>
  <div class="karte" data-produkt-id="2"><h3>Viper</h3></div>
</div>
Tipp, wenn du nicht weiterkommst

Log event.target und event.currentTarget und klick einmal mitten auf den Titel, einmal auf den Rand der Karte. Sie sind nicht immer gleich. Um vom geklickten Element zur Karte hochzukommen, gibt es eine Methode — such nach closest.

●●○ mittel

Vier Event-Typen und ein Abschied

Bau ein Suchfeld und probier vier Ereignisse aus: input, change, focus, keydown. Gib jeweils aus, wann sie feuern. Dann: Ein Button soll nur beim ersten Klick wirken — nimm den Listener danach wieder ab.

Tipp, wenn du nicht weiterkommst

Tipp in das Feld, verlass es, komm zurück, drück Tasten — und log bei jedem Ereignis, wann es feuert. Für „nur einmal“ gibt es zwei Wege: sich im Handler selbst abmelden, oder eine Option als dritten Parameter. Beim Abmelden muss es dieselbe Funktion sein, nicht nur dieselben Zeilen.

// 10

Events auf der Seite

Bisher hing jeder Listener an einem Element. Jetzt hört die ganze Seite zu — der Weg zu „Klick nach draußen schließt das Menü".

?

Fragen zum Erklären

  1. Wie hängst du einen Listener an die komplette Seite? Was ist der Unterschied zwischen document und window?
  2. Was bedeutet Bubbling?
  3. Was macht event.stopPropagation(), und wann brauchst du es?
Wo du nachschauen kannst

Stichwörter: „event bubbling“, „document vs window“, stopPropagation, Node.contains.

●●● schwer

Klick nach draußen schließt das Menü

Deine Navigation öffnet sich per Klick auf einen Button und bekommt dabei die Klasse show. Sie soll sich wieder schließen, wenn irgendwo außerhalb geklickt wird — ein Klick in der Navigation darf sie nicht schließen.

<button class="nav-toggle">Menü</button>
<nav class="nav">
  <a href="/schlaeger">Schläger</a>
  <a href="/baelle">Bälle</a>
</nav>
Tipp, wenn du nicht weiterkommst

Zwei Listener: einer am Button, einer am document. Im zweiten brauchst du eine Methode, die fragt, ob ein Element innerhalb eines anderen liegt — nicht classList.contains, sondern die für den DOM-Baum. Wenn dein Menü sich nie öffnet, dann weil der Klick auf den Button auch beim document ankommt; das Stichwort dazu heißt Bubbling.

●●○ mittel

Escape schließt, Enter sucht

Erweiter die Navigation: Die Taste Escape schließt sie ebenfalls. Und im Suchfeld soll Enter die Suche auslösen, ohne dass die Seite neu lädt.

Tipp, wenn du nicht weiterkommst

Der Tastenname steht als String in event.key — log ihn und drück ein paar Tasten, dann kennst du die Schreibweise. Groß- und Kleinschreibung zählt. Denk beim Schließen daran, wo der Tastaturfokus danach landet.

localStorage

Werte, die einen Seitenwechsel überleben. Zwei Methoden, ein Datentyp — und daraus folgt die halbe Aufgabenliste.

?

Fragen zum Erklären

  1. Wofür brauchst du den localStorage?
  2. Was ist der Unterschied zum sessionStorage?
  3. Welche Methoden gibt es, und was für Werte kann man speichern?
  4. Wo in den DevTools siehst du den Inhalt, und wie löschst du ihn dort?
Wo du nachschauen kannst

Stichwörter: localStorage, sessionStorage, „setItem getItem removeItem clear“, „storage limit“, „DevTools Application tab“.

●●○ mittel

Ein Zähler, der das Neuladen übersteht

Bau eine Seite mit einem Button und einer Zähleranzeige. Jeder Klick erhöht den Zähler um 1 und speichert ihn. Beim Laden der Seite wird der gespeicherte Wert angezeigt — ist noch keiner da, steht 0. Lade die Seite mehrfach neu und prüf es.

Tipp, wenn du nicht weiterkommst

Prüf mit typeof, was getItem zurückgibt — der Storage kennt nur einen Datentyp. Wandle den Wert deshalb beim Lesen um, nicht erst beim Rechnen. Probier zum Beweis bewusst z = z + 1 statt z++ und schau, was in der Anzeige steht. Und denk an den ersten Besuch, wenn noch nichts gespeichert ist.

●○○ leicht

Löschen — einzeln und komplett

Bau zwei Buttons: einer leert nur den Warenkorb, der andere löscht alles aus dem Storage. Speicher vorher drei verschiedene Schlüssel, damit du den Unterschied siehst. Prüf das Ergebnis im Application-Tab.

Tipp, wenn du nicht weiterkommst

Es gibt eine Methode für einen einzelnen Schlüssel und eine für alles. Log nach jedem Klick localStorage.length und prüf im Application-Tab, was übrig ist. Überleg dabei, was ein „alles löschen“ in einem echten Projekt mit der Consent-Entscheidung macht.

●○○ leicht

Der Unterschied zum sessionStorage, praktisch

Leg denselben Wert in beide Speicher. Dann: Seite neu laden — was ist noch da? Tab schließen und die Seite in einem neuen Tab öffnen — was ist jetzt noch da? Sag es vorher.

Tipp, wenn du nicht weiterkommst

Beide haben dieselben Methoden, du kannst den Code also kopieren. Der Unterschied zeigt sich nicht beim Neuladen — dafür musst du den Tab schließen und die Seite neu öffnen. Sag vorher, was du erwartest.

●●● schwer

Der ganze Warenkorb

Die Königsaufgabe dieses Themas. Auf der Produktliste legt ein Klick auf „In den Warenkorb" das Objekt des geklickten Artikels ab (id, name, preis). Im Warenkorb-Bereich werden alle gespeicherten Artikel ausgelesen und als HTML angezeigt, mit Gesamtsumme. Ein leerer Warenkorb zeigt eine Meldung.

Hier laufen alle bisherigen Themen zusammen: Array-Methoden, Data-Attribute, Event Delegation, createElement und Storage.

Tipp, wenn du nicht weiterkommst

Der Storage kann keine Objekte speichern. Es gibt zwei eingebaute Funktionen, die zwischen Objekt und String übersetzen — such nach JSON.stringify. Bau dir zwei kleine Hilfsfunktionen zum Laden und Speichern, dann steht die Umwandlung nur an einer Stelle. Zwei Fallen: Beim ersten Besuch ist noch nichts da (was gibt getItem dann zurück, und was macht JSON.parse damit?), und der Warenkorb-Bereich muss geleert werden, bevor du ihn neu füllst — sonst wächst er bei jedem Klick.

Cookies

Der ältere Bruder des Storage — kleiner, unbequemer, aber er geht bei jeder Anfrage zum Server mit. Deshalb hängt an ihm die Consent-Frage.

?

Fragen zum Erklären

  1. Was ist ein Cookie, und was sind die typischen Anwendungsfälle?
  2. Was ist der Unterschied zum localStorage?
  3. Welche Attribute kann ein Cookie haben?
  4. Kann man ein Cookie auch ohne JavaScript setzen?
Wo du nachschauen kannst

Stichwörter: document.cookie, „cookie attributes“, „max-age expires“, SameSite, HttpOnly, Set-Cookie.

●●○ mittel

Cookie setzen und lesen

Bau einen Button, der ein Cookie besuch=erster mit 7 Tagen Laufzeit setzt. Gib danach document.cookie in der Konsole aus und schau es dir im Application-Tab an. Schreib dann eine Funktion leseCookie(name), die einen einzelnen Wert zurückgibt.

Tipp, wenn du nicht weiterkommst

Beim Schreiben sieht document.cookie = ... wie eine Zuweisung aus, verhält sich aber nicht so — setz zwei Cookies hintereinander und log danach. Beim Lesen bekommst du alle in einem String: zerleg ihn mit split und such den richtigen Teil heraus. Für die Laufzeit ist max-age in Sekunden einfacher als ein Datum.

●●○ mittel

Cookie löschen

Bau einen zweiten Button, der das Cookie wieder entfernt. Es gibt kein deleteCookie — finde heraus, wie man es trotzdem loswird.

Tipp, wenn du nicht weiterkommst

Es gibt keine Löschmethode. Überleg, was mit einem Cookie passiert, wenn seine Laufzeit vorbei ist — und ob du das selbst herbeiführen kannst. Falls das Löschen scheinbar nicht wirkt: Vergleich im Application-Tab den path mit dem, den du beim Setzen angegeben hast.

●●● schwer

Das Consent-Modal

Die praktische Aufgabe dieses Themas. Beim Laden der Seite öffnet sich ein Modal mit einem Datenschutztext (nimm einen beliebigen aus dem Netz). Es lässt sich nur über „Zustimmen" schließen — nicht per Escape, nicht per Klick daneben. Der Klick setzt ein Cookie; bei allen späteren Besuchen bleibt das Modal zu. Im Footer liegt ein Link, der es jederzeit wieder öffnet.

Tipp, wenn du nicht weiterkommst

Nimm das HTML-Element <dialog> mit showModal() — es bringt Abdunkelung, Klicksperre und Tastaturfokus schon mit, das ersparst du dir. Escape schließt es aber trotzdem: Such nach dem Ereignis cancel und überleg, was du darin aufrufen musst (das kennst du aus Thema 09). Beim Laden entscheidet das Cookie, ob das Modal überhaupt aufgeht.

fetch

Daten von einem Server holen und in die Seite bringen. Hier zahlt sich alles aus: Arrays, Schleifen, createElement und Event Delegation auf einmal.

?

Fragen zum Erklären

  1. Was macht fetch?
  2. Warum braucht es then — warum steht das Ergebnis nicht einfach in einer Variablen?
  3. Wofür ist catch, und was fängt es nicht?
  4. Was macht appendChild?
Wo du nachschauen kannst

Stichwörter: „fetch API“, promise, „then catch“, response.ok, response.json, appendChild.

●○○ leicht

Der erste fetch

Hol die 100 Posts von https://jsonplaceholder.typicode.com/posts und gib sie in der Konsole aus. Log dazwischen auch die Antwort selbst und schau dir an, was darin steht. Setz danach ein console.log("fertig") direkt nach den fetch-Aufruf — in welcher Reihenfolge erscheinen die Meldungen?

Tipp, wenn du nicht weiterkommst

Es braucht zwei then — überleg, warum: Was du im ersten in der Hand hast, ist noch nicht die Liste. Log es dir an, dann siehst du es. Vergiss im ersten das return nicht. Setz danach ein console.log("fertig") hinter den ganzen Aufruf und achte genau auf die Reihenfolge in der Konsole — die überrascht.

●●○ mittel

Wenn die API nicht antwortet

Erweiter den fetch um catch. Dann provozier zwei verschiedene Fehler und schau, welcher im catch landet:

  1. eine Adresse, die es auf dem Server nicht gibt (/postsXYZ)
  2. eine Domain, die gar nicht existiert (https://gibtsnicht.example)
Tipp, wenn du nicht weiterkommst

Nur einer der beiden Fälle landet von allein im catch; probier beide. Log für den anderen response.status und response.ok — daran siehst du, was du selbst prüfen und mit throw auslösen musst. Und zeig den Fehler auf der Seite, nicht nur in der Konsole: Der Nutzer sieht die Konsole nie.

●●● schwer

Die Posts auf der Seite darstellen

Die Abschlussaufgabe. Leg ein leeres <div id="liste"></div> an. Bau für jeden Post per createElement eine Karte aus Titel und Text und häng sie mit appendChild ein. Zeig nur die ersten zehn. Ein Klick auf eine Karte gibt ihre ID in der Konsole aus.

Tipp, wenn du nicht weiterkommst

Alles, was du brauchst, hattest du schon: eine Methode für die ersten zehn (Thema 06), forEach, createElement, appendChild — und textContent statt innerHTML, weil die Texte von einem fremden Server kommen. Für den Klick häng den Listener an den Container und nicht an die Karten: Überleg, warum das hier nicht anders geht.
